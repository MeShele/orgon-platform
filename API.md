# API

Two surfaces live in this repo:

| Surface | Audience | Auth |
|---|---|---|
| **`/api/*`** | ORGON dashboard (operators) | JWT bearer |
| **`/v1/*`** | B2B merchants (exchangers, banks, exchanges) | HMAC-signed |

Canonical schema for both is the **live OpenAPI** generated by FastAPI:

| Surface | URL |
|---|---|
| Swagger UI | `https://<api-host>/api/docs` |
| ReDoc | `https://<api-host>/api/redoc` |
| OpenAPI JSON | `https://<api-host>/api/openapi.json` |

The OpenAPI schema is the source of truth for request/response shapes —
don't pin them in markdown, they'll go stale.

For integrators a guided onramp lives at
[`/developers`](https://orgon.asystem.ai/developers) (quickstart, HMAC
snippets, webhook verify, sample apps, error catalog).

---

## /api/* — operator dashboard

JWT-bearer. Authentication: `POST /api/auth/login` → access (8h) +
refresh (7d). Refresh via `POST /api/auth/refresh`. Login is rate-
limited to **5 attempts/min/IP**; general API is 100 req/min/IP.

`JWT_SECRET_KEY` is required env on prod — the auto-generated fallback
rotates on container restart and silently invalidates every issued
token.

Multi-tenancy: every authenticated request resolves the user's active
`organization_id`. RLS policies on `wallets / transactions / signatures
/ contacts / scheduled_transactions / audit_log`. `super_admin` users
bypass via the `orgon_current_org_or_super()` SQL helper.

The dashboard itself (Next.js, `/dashboard`, `/wallets`, `/settings`,
`/admin/merchants`, …) drives everything off this surface — it's the
same API the operator sees.

## /v1/* — B2B Merchant API

For external integrators (an exchanger's backend, a bank's payments
microservice, a custody-as-a-service consumer). Replaces the
deprecated `/api/v1/partner/*` family that was removed in migration
033.

### Authentication

Every `/v1/*` call carries four headers:

| Header | Value |
|---|---|
| `X-ORGON-Key` | public id, `okl_<32hex>` (live) or `okt_<32hex>` (sandbox) |
| `X-ORGON-Timestamp` | Unix milliseconds, must be within ±60s |
| `X-ORGON-Nonce` | UUIDv4, unique per call within the timestamp window |
| `X-ORGON-Signature` | `hex(HMAC-SHA256(secret, msg))` |

`msg` is `f"{ts}\n{nonce}\n{METHOD}\n{path}\n".encode() + raw_body`.
Body is the raw bytes the client sends — no canonical-json voodoo.

Secrets are issued exactly once (one-time-reveal modal in
`/settings → API ключи`); we store a bcrypt hash plus a pgcrypto-
encrypted copy that the HMAC middleware decrypts in-memory to
recompute the signature. The wrapping key is the `MERCHANT_KEY_MASTER`
env var.

Per-IP rate limit: **300 req/min/IP** at the edge (circuit breaker
before HMAC verify). Per-merchant daily quotas come from the pricing
plan — see Billing below.

Replay protection: `(key_pub, nonce)` is a PK on
`merchant_request_nonces`; collision = 401. Pruned every 15 min by the
scheduler.

### Endpoint catalog

```

  GET    /v1/transactions?wallet_id=&cursor=&limit=

  GET    /v1/wallets/{wallet_id}/deposits

Webhooks
  GET    /v1/webhooks/config

  GET    /v1/webhooks/deliveries

  GET    /v1/usage                              # today's counters + plan limits + 30-day history
  GET    /v1/invoices

  GET    /v1/networks                           # supported networks reference
  GET    /v1/ping                               # authenticated echo
```

### Error envelope

Every 4xx/5xx response shares one shape:

```json
{
  "error":   "<machine-readable code>",
  "message": "<human-readable>",
  "request_id": "<uuid hex>",
  "details": [ … ]
}
```

Canonical codes:

| Code | HTTP | When |
|---|---|---|
| `unauthorized` | 401 | bad signature, expired/revoked key, replay |
| `rate_limited` | 429 | daily plan quota or 300/min/IP |
| `sandbox_restricted` | 400 | sandbox key tried to hit a mainnet network |
| `validation_error` | 422 | body failed pydantic — see `details` |
| `not_found` | 404 | resource doesn't exist or belongs to another merchant |
| `conflict` | 409 | identifier already in use |
| `upstream_error` | 502 | Safina returned an error |
| `internal_error` | 500 | unexpected; quote `request_id` to support |

Every response (including 2xx) carries `X-Request-Id`. Paste it into
support and we trace the full path in our logs.

### Supported networks

Provisioning via Safina; deposit watcher reads each chain's public
explorer.

| ID | Name | Native | Tokens | Watcher source |
|---|---|---|---|---|
| 1000 | Bitcoin | BTC | — | Blockstream Esplora |
| 3000 | Ethereum | ETH | USDT, USDC | Etherscan |
| 3040 | Ethereum Sepolia | ETH | (per contract) | Sepolia Etherscan |
| 5000 | Tron | TRX | USDT, USDC, LDFT, … | TronGrid |
| 5010 | Tron Nile testnet | TRX | USDT, LDFT, … | TronGrid Nile |

ETH watcher honours `ETHERSCAN_API_KEY` env when set (5 req/s with key,
1 per 5s without). ORGON's own chain (5800/5810) is provisioned in
Safina but not yet watcher-supported pending their explorer API.

### Multi-sig

Wallet `slist` is set at creation via Safina. ORGON auto-injects
`min_signs: "1"` plus either the merchant's EC (treasury) or the
merchant's EC + end-user's email (user_deposit) — verified end-to-end
on 2026-05-14 against Safina's monitor.

`POST /v1/transactions/{tx_id}/sign` is idempotent on
`(tx_unid, signer_address, action)`; duplicate sign returns **409**
with `error="conflict"`. Sentinel `tx_hash` values like
`"Transaction canceled, 1 day limit."` are mapped to `status="canceled"`
in our response shape.

### Webhooks

Outbound: ORGON POSTs each event to the merchant's configured
`webhook_url` with HMAC signature in headers:

```
X-ORGON-Webhook-Timestamp:  <unix ms>
X-ORGON-Webhook-Signature:  hex(HMAC-SHA256(webhook_secret, ts + "\n" + body))
X-ORGON-Webhook-Id:         <delivery uuid>
X-ORGON-Webhook-Event:      <event type>
User-Agent:                 Orgon-Webhook/1.0
```

Verify with **`WebhooksAPI.verify(...)`** in the TypeScript SDK or
**`verify_webhook(...)`** in the Python SDK.

Retries: 30s → 2m → 10m → 1h → 6h, six attempts; then marked
permanently failed (still visible via `GET /v1/webhooks/deliveries`).

Event types:

| Type | Fires when |
|---|---|
| `wallet.activated` | Safina issues the on-chain address |
| `wallet.deposit.detected` | inbound on-chain transfer seen by our watcher |
| `transaction.broadcasted` | outbound tx broadcast to chain |
| `transaction.confirmed` | tx reached configured confirmations |
| `transaction.failed` | tx canceled/failed |
| `user.created` | echo after `POST /v1/users` (audit) |
| `webhook.test` | manual via `POST /v1/webhooks/test` |

### Pricing & quotas

Daily limits per plan (rolling 00:00 UTC):

| Plan | api_calls/day | tx_count/day | active_users/day | base USD/mo |
|---|---|---|---|---|
| sandbox | 5 000 | 100 | 50 | 0 |
| starter | 50 000 | 1 000 | 500 | 99 |
| growth | 500 000 | 10 000 | 10 000 | 499 |
| enterprise | unlimited | unlimited | unlimited | 2 499 |

Overage on starter/growth: $0.10/1000 API calls + $0.05/tx (starter),
$0.05/1000 + $0.02/tx (growth). Enterprise is flat.

Invoice generation runs daily at **02:00 UTC** (idempotent catch-up) —
one invoice per (merchant, calendar month). Visible to merchant via
`GET /v1/invoices`, and to platform-admin via
`GET /api/admin/merchants/{id}/invoices`.

### Sandbox

Issue a key with `sandbox: true` → prefix `okt_*`. Sandbox merchants
are restricted on the backend: any attempt to provision a wallet on a
mainnet network (1000, 3000, 5000, 5800) returns
`400 sandbox_restricted`. Testnets: 1010 (deferred), 3040, 5010, 5810.

## /api/admin/merchants/* — platform-admin

Super-admin / platform-admin endpoints used by `/admin/merchants` in
the dashboard.

```
GET    /api/admin/merchants                              list with counts
POST   /api/admin/merchants                              onboard new
GET    /api/admin/merchants/{id}
PATCH  /api/admin/merchants/{id}                         settings, plan, sandbox, webhook, status
GET    /api/admin/merchants/{id}/api-keys
POST   /api/admin/merchants/{id}/api-keys                issue — secret returned ONCE
POST   /api/admin/merchants/{id}/api-keys/{key_id}/revoke
GET    /api/admin/merchants/{id}/usage                   counters + 30-day history
GET    /api/admin/merchants/{id}/invoices
POST   /api/admin/merchants/{id}/invoices/{invoice_id}/paid   back-office only
```

JWT-scoped — caller must be `super_admin` / `platform_admin` / `admin`
of the target merchant.

## SDKs

| Language | Package | Source |
|---|---|---|
| TypeScript / Node ≥ 18 | `@orgon/sdk` | `sdks/typescript/` |
| Python ≥ 3.10 | `orgon-sdk` | `sdks/python/` |

Both follow the same resource layout:

```ts
orgon.users.create({ external_id, email })
orgon.wallets.create({ network: 5010, end_user_id })
orgon.transactions.send({ wallet_id, to_address, amount })
orgon.transactions.sign(tx_id)
orgon.deposits.listForUser(user_id)
orgon.webhooks.config.update({ url, secret })
orgon.webhooks.test()
orgon.invoices.list()
```

The TS SDK publishes to npm under `@orgon/` via
`.github/workflows/sdk-publish.yml` on `sdk-v*` tag push (provenance
on). The Python SDK ships from the repo for now; PyPI publish is
similarly tag-driven (planned).

Sample apps live under `sdks/typescript/examples/`:

* `payment-receiver` — Express server that onboards users, exposes
  deposit addresses, credits a ledger on `wallet.deposit.detected`.
* `payout-sender` — CLI that walks the full outbound flow end-to-end.

A backend signature-drift test
(`backend/tests/test_b2b_hmac.py`) pins the exact byte layout of the
signing message so any accidental protocol rotation trips CI before
integrators see broken HMAC.
